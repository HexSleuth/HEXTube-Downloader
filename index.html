    Self-host it

    VidGrab is a static file — but it needs a backend to actually pull media. Pick one of the stacks below. Everything here is copy-paste ready.

    1 · MeTube (yt-dlp web UI)

    MeTube is a self-hosted web UI for yt-dlp. Paste a link, it downloads to your server — single videos, playlists or whole channels.

    • Runs in Docker, listens on port 8081
    • Downloads land in ./downloads
    • Full yt-dlp option passthrough via YTDL_OPTIONS
    docker-compose.yml

    2 · cobalt API (what this page talks to by default)

    cobalt is a privacy-first media downloader. Its API is a single POST / endpoint that returns a tunnel or redirect URL — no ads, no trackers.

    • Default port 9000
    • Set API_URL to the public URL of your instance
    • If you enable Turnstile, VidGrab will pop the challenge automatically
    • If you enable an API key, paste it in ⚙ Settings → cobalt → API key
    • If you leave both disabled, VidGrab works with no auth at all
    docker-compose.yml

    3 · Minimal PHP + yt-dlp backend

    This is the web-youtube-downloader / Jayasakthi-07 approach: two PHP files wrapping yt-dlp, served by nginx. VidGrab can talk to it in yt-dlp API mode.

    • api.php — returns { title, links:[{url,format,itag,…}] }
    • download.php — streams the media back with a real filename
    • In VidGrab: ⚙ Settings → Engine = yt-dlp, API base = https://your-host, proxy = https://your-host/download.php?video_url=
    public/api.php
    public/download.php
    nginx.conf
    docker-compose.yml
    Dockerfile (php + yt-dlp)

    4 · Deploy this page on GitHub Pages

    This file is 100% static — no build step, no dependencies, no CDN.

    • Save it as index.html in your repo root
    • Repo → Settings → Pages → Source: Deploy from a branch → main / /root
    • Open https://<user>.github.io/<repo>/
    • If the public cobalt instance is blocked, self-host cobalt and set your own URL in ⚙ Settings

    How VidGrab handles cobalt auth

    • cobalt v10+ requires a short-lived JWT session token for its official instance, issued after a Cloudflare Turnstile challenge.
    • On first download VidGrab calls GET /session, detects whether auth is needed, runs the challenge if present, then POST /session to obtain the JWT.
    • The JWT is cached in localStorage and attached as Authorization: Bearer …. Expired or rejected tokens are refreshed automatically and the request is retried once.
    • Instances that use API keys instead are supported via Authorization: Api-Key …. You can also paste a bearer token manually.
    • Instances with no auth (typical self-hosted setup) work without any token.
    • Turnstile sitekeys are usually domain-restricted: the official instance's challenge will not succeed when this page is hosted on GitHub Pages. Self-host cobalt, or use the yt-dlp engine.
